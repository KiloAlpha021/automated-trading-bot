## Narrow implementation and prerequisites

The accepted M1.6 baseline is commit
`f4c939846ee732267e5cf2287331be4997fc034f` with 331 passing tests.
No existing contract requires modification. This M1.7 slice uses only standard
library Enum and immutable dataclass primitives in the existing domain package.
It supplies mode data, not a runtime operations service or a state machine.

Local engineering requirement M1.7-STARTUP-01: a new OperationalState defaults
to NO_NEW_ORDERS, independently of previous instances.
Local engineering requirement M1.7-VALIDATION-01: only OperationalMode values
are accepted; strings, booleans, None and unknown data fail explicitly.
Local engineering requirement M1.7-AUTHORITY-01: without an independently
implemented authorization/reconciliation gate, NORMAL and DEGRADED are rejected.
These local requirements describe the milestone slice and do not mark all of
IMP-016 or the later operational test catalogue complete.

Rejecting both potentially permissive modes is a conservative engineering
choice; the canonical specification does not prescribe a constructor API.
The canonical vocabulary retains their names. No boolean authorization switch,
approval shortcut, restore API or activation method is introduced. Therefore
stale, expired or even current approval metadata cannot activate this model;
M1.6 remains responsible for its own deterministic validity checks.
Restrictive modes are descriptive: CANCEL_ONLY grants no cancellation authority,
and scoped disable labels grant no permission outside their scope. Future
operations ownership, scoped restriction composition, controlled transitions,
reconciliation, audit emission, persistence, recovery and operational permission
evaluation are deferred. Risk, Compliance, OMS and execution remain separate.

## Acceptance evidence

`tests/test_operational_mode.py` contains 26 deterministic cases covering default
startup, every restrictive mode, rejection of NORMAL/DEGRADED, invalid and unknown
input, immutability, independent fresh startup and absence of an authorization
shortcut. Tests were added first; collection initially failed because the module
was absent, then all 26 passed after implementation. No sleeps, external services,
wall clock, local timezone assumptions or shared mutable state are used.

No production capability, broker/database dependency, persistence, event bus,
risk engine or third-party dependency is added. M1.8 is not started.
